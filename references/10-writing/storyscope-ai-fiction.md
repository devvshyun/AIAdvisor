# AI가 쓴 글은 문체가 아니라 이야기 구조에서 걸립니다 (StoryScope)
- 원문: https://lazyowen.com/guides/storyscope-ai-fiction
- 도구·주제: StoryScope(논문 + GitHub 저장소) + Claude/ChatGPT 진단 프롬프트 · 글쓰기 / AI 티 제거 (공부·리서치, 13분 읽기, STEP 8개, 2026-08-18 공개)
- 한 줄 요약: 문체가 아니라 "이야기를 짜는 방식(서사 구조)"으로 AI 소설을 93.2% 가려낸다는 StoryScope 논문을 정리하고, 내 글을 같은 기준으로 진단·수정하는 체크리스트와 프롬프트를 제공한다.

## 언제 쓰나
- 내가 쓴(또는 AI와 같이 쓴) 글이 구조 차원에서 AI처럼 보이는지 점검하고 싶을 때. 문체만 다듬어도 AI 티가 안 지워지는 이유를 알고 싶을 때.
- 주의: 연구 대상은 소설. 릴스 대본·블로그에는 "주제를 떠먹이지 않는다", "구조를 한 줄로 펴지 않는다" 같은 원리만 가져오고 수치를 그대로 옮기지 말 것.

## 준비물 / 필요 도구
- 논문: StoryScope: Investigating idiosyncrasies in AI fiction (COLM 2026) — 초록 https://arxiv.org/abs/2604.03136 · PDF https://arxiv.org/pdf/2604.03136 (v6)
- 저자: Jenna Russell, Rishanth Rajendhran, Chau Minh Pham, Mohit Iyyer (University of Maryland, College Park), John Wieting (Google DeepMind)
- 공식 GitHub: https://github.com/jenna-russell/storyscope — 파이프라인 코드, 프롬프트 10,272개, AI 생성 서사 51,336편. 사람 소설 원문은 저작권 때문에 비공개(Books3 원본을 따로 구해야 함).
- 진단용: ChatGPT 또는 Claude 대화창. 논문·저장소·가이드 모두 무료.
- 가이드 PDF(A4 9쪽): https://lazyowen.com/guide-pdf/storyscope-ai-fiction.pdf

## 단계별 방법
### 요약 3줄 (Quick Start)
- 단서는 문체가 아니라 이야기 구조: 단어·문장 길이를 안 보고 구조만으로 93.2%.
- AI는 독자를 못 믿음: 주제를 직접 설명, 감정을 몸의 감각으로 번역, 줄거리를 한 줄로 폄. 사람은 빈칸을 남기고 시간을 흔듦.
- 모델마다 버릇이 다름.

### STEP 1. 연구가 던진 질문
- 기존 AI 탐지는 문체(단어 선택, 문장 길이, 반복 표현)를 봤지만 "더 사람처럼 고쳐줘"나 몇 문장 손질로 쉽게 지워짐.
- 연구진은 표현이 아닌 서사 특징(주인공 수, 시간 순서, 열린 결말 등 이야기를 구성하는 선택)에 걸었음. 글을 통째로 다시 쓰지 않으면 잘 안 바뀜.

### STEP 2. 실험 설계
1. 사람 소설 10,272편(Books3)에서 "이 글을 쓰게 할 주문"을 역으로 뽑아 프롬프트 10,272개 생성.
2. 같은 프롬프트를 AI 5종(Gemini 3 Flash, Kimi K2.5, DeepSeek V3.2, Claude Sonnet 4.6, GPT-5.4)에 투입 → 총 61,608편(사람 10,272 + AI 51,336, 평균 약 4,753단어). 주제를 묶어 남는 차이가 곧 작성자의 버릇.
3. 처리 3단계: ① 문체를 버리고 인물·사건·시간 등 구조 표로 변환(NarraBench 분류 체계) ② 같은 프롬프트의 여섯 편을 맞대어 비교(비용 때문에 600편 사용) ③ 갈리는 지점을 사람이 읽을 항목으로 정리해 특징 304개 도출. 여기까지 GPT-5.1이 수행, 304개를 전체 61,608편에 매기는 작업은 Gemini 3 Flash.
4. 점수표를 학습시켜 판별에 쓰이는 핵심 특징 30개, 모델 지문 특징 75개를 추림.

### STEP 3. 결과 (macro-F1: 사람/AI를 고르게 맞혔는지, 100에 가까울수록 좋음)
| 무엇을 봤나 | macro-F1 |
|---|---|
| 이야기 구조만 (문체 안 봄) | 93.2 |
| 구조 + 문체 | 96.0 |
| 핵심 특징 30개만 | 84.8 |
| 핵심 30개 + 모델 지문 | 91.1 |
| 누가 썼는지 6지선다 (구조만) | 68.4 (문체 포함 77.3) |
- 길이를 맞춰도 성능 동일(길이 때문이 아님).
- 문체 리라이팅(Gemini 글 278편을 LAMP 리라이터로 다듬음): 95.5 → 93.9, 겨우 1.6포인트 하락 → 글자를 고쳐서는 구조 신호가 안 지워짐.

### STEP 4. AI 글의 세 가지 습관
1. 주제를 대놓고 설명: 화자가 교훈을 직접 말함, 대화를 철학 논쟁에 사용, 다른 작품은 실명 대신 흐릿한 암시.
2. 감각·신체 과다 묘사: 감정을 이름 대신 몸의 감각으로(특히 냄새), 속마음 깊이 파고들기, 배경을 심리의 거울로. (사람은 감정을 그냥 이름으로 부르는 쪽이 많음)
3. 구조 단순화: 인과가 한 줄, 곁가지 없음, 인물을 겉모습으로 소개, 첫 장면에서 장소를 또렷이 못 박음, 결말을 선택/깨달음으로 깔끔히 닫음.

### STEP 5. 사람 글이 하는 것
- 다른 작품을 실명으로 부르고 직접 인용도 섞음
- 독자에게 말을 걺(제4의 벽 깨기)
- 회상·시간 도약, 중요한 사실을 늦게 꺼내 긴장 형성
- 인물을 도덕적으로 애매한 선택 앞에 세움, 곁가지 이야기 더 많음
- 사람 글이 훨씬 다양: 특징 좌표에서 AI 5종은 한 덩어리, 사람만 넓게 퍼짐. 오분류는 대부분 AI끼리의 혼동.

### STEP 6. 모델별 서사 지문
(문체 포함/구조만 점수: 사람 93.0/88.5, Claude 89.3/77.1, GPT 82.1/73.0)
- Claude: AI 중 가장 뚜렷. 사건을 세게 몰아붙이지 않고 화자 목소리가 일정, 전통적 이야기 관습을 지킴.
- GPT: 소문·뒷말을 사건 장치로 사용, 지난 일을 멀리서 회고하는 형태, 사람 사이의 관계에 무게.
- Gemini: 인물을 겉모습으로 소개, 긴 결말 정리로 말끔하게 닫음, 어두운 배경(배경의 88%가 음울).
- DeepSeek: 중요한 맥락을 초반에 먼저 노출.
- Kimi: 구별되는 선택이 가장 적음(5종 평균값 자리).
- Gemini/DeepSeek/Kimi는 서로 헷갈리는 무리.

### STEP 7. 내 글에 적용하기 (순서대로, 앞 4개는 빼기 / 뒤 4개는 넣기)
- [ ] 화자가 주제·교훈을 직접 말하는 문장 → 지우고 장면으로 대체
- [ ] 감정을 몸의 감각·냄새로 바꾼 곳이 몰려 있으면 2~3곳 → 1곳으로 축소
- [ ] 인과가 한 줄이면 곁가지 하나 추가하거나 설명 한 겹 덜기
- [ ] 결말이 너무 말끔하면 답 하나를 남기고 끝내기
- [ ] 흐릿한 암시를 실제 작품·사람·사건의 실명으로
- [ ] 독자에게 직접 말을 거는 문장 한 번 삽입
- [ ] 시간이 순서대로만 흐르면 중요한 사실 하나를 뒤로 미루기
- [ ] 판단이 한쪽으로만 정리됐다면 애매한 선택 하나 남기기

진단 프롬프트 (프롬프트 뼈대):
- 역할: 내 한국어 글이 StoryScope 기준으로 AI처럼 보이는지 진단하는 편집자. 슬롯: <검사할 글 원문>, <글의 용도 예: 릴스 대본>, <읽는 사람 예: AI 처음 쓰는 직장인>.
- 작업 4단계: ① AI 쪽 항목 판정(주제·교훈 직접 말하기 / 감각·냄새 번역 / 한 줄 인과·곁가지 없음 / 깔끔한 결말) ② 사람 쪽 항목 대비 부족분(작품·작가 실명 / 독자에게 말 걸기 / 시간 흔들기 / 도덕적 애매한 선택) ③ 항목별 원문 인용 문장과 고친 문장 나란히(전체 재작성 금지) ④ 초보자용 요약(가장 큰 이유와 다음 글의 규칙).
- 제약: 사실·숫자·고유명사·인용문 변경 금지, 단어만 바꾸고 끝내기 금지, 원문에 없는 근거 지어내기 금지. 출력: 항목별 판정표, 인용·수정 쌍, 마지막 5줄 정리.
- 검증: 모든 판정에 원문 근거 문장을 인용, 못 찾은 항목은 "확인 불가"로 두기, 근거 없이 단정한 항목이 있으면 완료 보고 금지.
- 사용법: 프롬프트 복사 → 꺾쇠 자리 채워 Claude/ChatGPT에 실행 → 판정과 근거가 함께 나오는지 확인 → 근거 없는 항목만 다시 질문. (인용 없는 판정은 AI가 지어낸 것일 수 있으므로 믿지 말 것)

### STEP 8. 원문 직접 읽기
- PDF에서 먼저 볼 곳 3군데: ① 성능 표(조건별 숫자) ② 핵심 30개 + 지문 75개 특징 목록(체크리스트를 늘릴 때 활용) ③ 특징 공간 시각화(AI 5종은 뭉치고 사람은 퍼짐)
- 저장소 받기:
```bash
git clone https://github.com/jenna-russell/storyscope.git
```
성공하면 `storyscope` 폴더에 코드와 데이터가 생김. 사람 글 쪽을 다루려면 Books3 원본을 따로 구해야 함.

## 핵심 팁 · 주의사항
- ⚠️ 연구는 소설 대상. 다른 장르는 원리만 적용하고 수치는 일반화하지 말 것.
- ⚠️ 문체 다듬기만으로는 구조 신호가 안 지워짐 → 구조(주제 직설, 한 줄 인과, 말끔한 결말)부터 고칠 것.
- ⚠️ 진단 결과는 근거 문장이 붙은 것만 신뢰.
- ❌ AI가 쓴 초안의 단어만 교체 ✅ 장면화·곁가지·열린 결말·실명 인용·독자 호명·시간 흔들기·애매한 선택 추가
- 어떤 모델로 초안을 쓰느냐에 따라 지울 습관이 다름(STEP 6 참고).

- [ ] 인과가 한 줄이면 곁가지 추가
