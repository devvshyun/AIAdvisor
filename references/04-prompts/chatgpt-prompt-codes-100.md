# 챗GPT 쓸 때 모르면 손해인 코드 100개
- 원문: https://lazyowen.com/guides/chatgpt-prompt-codes-100
- 도구·주제: ChatGPT · 프롬프트 약속어(코드) 모음 (2026-10-09 공개, STEP 5개 · 약 14분)
- 한 줄 요약: 질문 앞에 ELI5, TLDR 같은 영어 코드 한 단어와 그 뜻 한 줄을 붙여 ChatGPT 답의 길이·난이도·말투를 바꾸는 방법과 코드 100개 목록(아래는 뜻을 요약한 것).

## 언제 쓰나
- 긴 프롬프트를 쓰기 부담스러운데 답을 더 쉽게/짧게/자연스럽게/비판적으로/구조화해서 받고 싶을 때
- 글 다듬기, 학습, 아이디어, 의사결정 분석 등 상황별로 형식·말투를 빠르게 바꿀 때
- 코드는 ChatGPT의 공식 명령어가 아니라 "뜻을 함께 적어 주는 약속어"(널리 쓰이는 TLDR, ELI5는 단어만으로도 통함)

## 준비물 / 필요 도구
- ChatGPT: https://chatgpt.com/ (브라우저, iOS·안드로이드·맥·윈도 앱). 설치·설정 불필요, OpenAI 제작
- 무료 플랜 안내: https://help.openai.com/en/articles/9275245-chatgpt-free-tier-faq · 앱 도움말 https://help.openai.com/en/collections/3742473-chatgpt
- 비용: 무료로 사용 가능, 코드를 붙인다고 추가 비용 없음. 무료 플랜은 사용량 한도가 있어 한도에 닿으면 초기화까지 기다리거나 유료 플랜 필요

## 단계별 방법
**Quick Start**: 아래 형태를 대화창에 붙여넣기(성공하면 어려운 용어 대신 일상 비유의 짧은 설명)
```
코드: ELI5
뜻: 다섯 살 아이에게 설명하듯 쉬운 말로 풀어 주세요
할 일: 인공지능이 어떻게 글을 쓰는지 설명해 주세요
```

**고민에 맞는 코드를 골라 첫 답까지 받는 프롬프트 뼈대** (ChatGPT 대화창)
- 역할: 챗GPT 코드 사용법을 알려 주는 프롬프트 코치. 맥락: 초보, 코드는 공식 명령이 아니지만 뜻을 같이 적으면 통함
- 채울 곳: [내 고민 — 예: 답이 너무 길다/설명이 어렵다/말투가 딱딱하다], [내 질문]
- 작업: ① 고민에 맞는 코드를 ELI5·TLDR·HUMAN·NO FLUFF·FEEDBACK LOOP·SPARRING PARTNER·REWRITE 중 하나 골라 이유 한 줄 ② `코드:` `뜻:` `할 일:` 세 줄 프롬프트 완성 ③ 그대로 내 질문에 실제 답변 ④ 안 맞을 때 같이 붙일 두 번째 코드 추천
- 제약: 위 7개 밖의 코드 지어내기 금지, 개인정보 재인용 금지, 한국어 답변. 검증: 세 줄이 모두 있고 답이 고른 코드의 뜻대로 나왔는지 자기 점검, 빠지면 완료 보고 금지

**STEP 1. 코드 붙이는 공식 익히기 (2분)**
- 기본: 코드만 붙이기 — `TLDR [긴 글 붙여넣기]`
- 더 확실하게(처음 보는 코드/형식이 분명할 때): 세 줄 공식
```
코드: [코드명]
뜻: [목록의 뜻 문장]
할 일: [내 질문이나 붙여넣을 글]
```
- 예: `코드: TLDR` / `뜻: 가장 짧고 쓸모 있는 요약으로 핵심만 알려 주세요` / `할 일: [요약할 글]` → 몇 줄짜리 핵심 요약이 오면 성공
- 뜻 줄은 아래 목록의 뜻을 복사해도 됨

**STEP 2. 읽기 쉽게 바꾸는 코드 3개 (3분)** — 하나씩 시험, 여러 개를 한꺼번에 붙이지 말 것(어느 코드가 효과를 냈는지 모름)
- ELI5(목록 9번): 5살에게 설명하듯 풀이. 예 `할 일: 금리가 오르면 대출 이자가 왜 늘어나는지` → 전문 용어 없는 비유 설명이면 성공
- TLDR(18번): 읽기 귀찮은 기사·메일 요약. 원문보다 훨씬 짧은 몇 줄이면 성공
- NO FLUFF(19번): 인사말·군더더기 빼고 결론부터. 예 `노트북 램은 몇 GB가 적당한지` → 첫 문장이 결론이면 성공

**STEP 3. 글을 사람답게 고치는 코드 2개 (3분)**
- HUMAN(1번): 딱딱한 AI 말투를 사람이 쓴 것처럼. 번역투가 줄고 말하듯 읽히면 성공
- REWRITE(2번): 핵심 내용은 두고 더 자연스러운 문장으로. 빠진 내용 없는지 원문과 한 줄씩 대조
- ❌ "HUMAN"만 붙이기(내 말버릇까지 지워질 수 있음) → ✅ 뜻 줄 끝에 "내 뜻과 말투는 유지해 주세요" 덧붙임

**STEP 4. 답을 더 깊게 만드는 코드 2개 (3분)**
- FEEDBACK LOOP(57번): 초안 → 스스로 부족한 점 찾기 → 고친 최종 답. 예 `퇴근 후 1시간 부업 아이디어` → 초안/부족한 점/최종 답이 차례로 보이면 성공
- SPARRING PARTNER(50번): 무조건 동의 말고 반대 의견과 허점 지적. `할 일`에 내 계획을 구체적으로(예산·기간·이유) 적을수록 정확
- ❌ "SPARRING PARTNER 해 줘"만 → 반박할 대상이 없어 일반론만 나옴

**STEP 5. 두 개 섞고 맥락 붙이기 (3분)** — 섞을 때는 뜻이 문장 안에 들어가게 쓰기. 예시 뼈대 3개
1. 놓친 가정 + 다음 행동: `HIDDENASSUMPTIONS로 내가 놓친 가정을 찾고, NEXTSTEP으로 다음에 할 만한 일 하나를 알려 주세요. 내 상황: [고민 중인 결정]` → 가정 목록 + 바로 시작할 행동 하나
2. 자연스럽게 고친 뒤 절반으로: `/human으로 자연스럽게 다시 쓴 다음 /shorten으로 절반 길이로 줄여 주세요. 내 뜻과 말투는 유지해 주세요: [내 글]`
3. 퀴즈: `QUIZME로 이 주제를 한 번에 한 문제씩 내 주세요. 제 답을 기다렸다가 맞은 점과 틀린 점을 설명하고 그다음 문제를 내 주세요: [공부할 주제]` → 문제 하나만 나오고 내 답을 기다리면 성공
- 맥락이 중요: 누가 읽을지·원하는 결과·참고 자료. ❌ `할 일: 이 보고서 요약해 주세요` → ✅ `팀장님께 보고할 수 있게 이 보고서를 3줄로 요약하고, 결정이 필요한 부분은 따로 표시해 주세요: [보고서]`
- FACTCHECK(56번)에는 "최신 자료를 검색해서 확인해 주세요"를 함께 적기. /predict(73번)처럼 앞날을 묻는 코드는 가정을 주고 가능한 결과를 여러 개 달라고 하면 구체적

## 핵심 팁 · 주의사항
- 코드 100개는 공식 기능이 아님 → 낯선 코드는 뜻 줄을 꼭 함께 적기
- ❌ 코드 3개를 한 질문에 한꺼번에 → ✅ 하나로 시작, 원하는 형식이 분명할 때만 두 개 섞기
- ❌ 지킬 것 없이 "HUMAN"만 → ✅ "내 뜻과 말투는 유지" 추가. 글을 고친 뒤엔 원문과 대조해 빠진 내용 확인
- ❌ 구체성 없는 SPARRING PARTNER → ✅ 예산·기간·이유가 든 구체적 계획
- 결과는 질문에 따라 달라지며 같은 답을 보장하지 않음. 사실 확인이 필요하면 최신 자료 확인을 요청하고 직접 검토
- 개인정보는 프롬프트에 넣지 말 것
