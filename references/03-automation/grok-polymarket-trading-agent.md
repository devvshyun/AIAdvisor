# 그록 50달러 자동매매 에이전트
- 원문: https://lazyowen.com/guides/grok-polymarket-trading-agent
- 도구·주제: Grok Bot (xAI, Cursor 계정) · Polymarket 모의(페이퍼) 매매 에이전트
- 한 줄 요약: Grok Bot이 10분마다 Polymarket 시장을 훑어 가상 $50으로 모의 거래하는 루틴을 만드는 방법. 실거래는 다루지 않음. (2026-10-08 갱신, 읽는 데 15분, 4단계 약 30분, 검증 기준일 2026-10-03)

## 언제 쓰나
- 예측 시장에서 AI 에이전트의 판단·리스크 규칙을 돈 안 쓰고 실험해 보고 싶을 때
- 원래 봇의 구조(10분 루프 + 거래당 6% 상한)를 이해하고 싶을 때. 예측 시장 = 질문에 예·아니오 지분을 사고파는 곳(지분 62센트 ≈ 확률 62%)

## 준비물 / 필요 도구
- Grok Bot: https://x.ai/bot (xAI 제작, 로그인·사용량은 Cursor 계정). 문서 https://docs.x.ai/grok-bot · 시작 https://docs.x.ai/grok-bot/get-started · 클라우드 컴퓨터/로그인 넘겨받기 https://docs.x.ai/grok-bot/computer-and-apps · 스킬·루틴 https://docs.x.ai/grok-bot/skills-routines-and-automations · 플랜/체험 https://cursor.com/help/grok-bot/plans
- 앱: 데스크톱 macOS·Windows·Linux(맥은 칩에 맞는 파일, 윈도는 x64/Arm64), 모바일 iPhone·iPad·Android. 상용 구독 서비스(공개 저장소 안내 없음).
- Polymarket Gamma API(읽기 전용, 키 불필요): https://gamma-api.polymarket.com · 지역 제한 문서 https://docs.polymarket.com/api-reference/geoblock
- 로컬 실습(선택): `python3`, `curl` (맥 기본 터미널: Spotlight ⌘+스페이스 → "터미널")
- 비용: Cursor 유료 개인 플랜(Pro 월 $20부터) 또는 개인 SuperGrok / SuperGrok Plus / SuperGrok Heavy / X Premium+ 연결. 체험은 7일 사용량 크레딧(자동 유료 전환 없음, iOS 앱스토어 체험은 예외).
- 용어: 정산=결과 확정 후 맞힌 쪽에 지급, 청산=정산 전 지분을 팔고 나오기, %p=확률끼리의 차이, 유동성=시장에 걸린 주문 금액, CLOB 호가창=가격별 사자·팔자 주문 목록, 슬리피지=주문가와 체결가 차이.

## 단계별 방법
**에이전트 구조 한눈에**: 카드뉴스 요소 ↔ 이 자료 위치 — $50 시작=STEP 4 헌장(가상 잔고 50달러) / 10분마다 최대 1,000개 스캔=STEP 2 / 가격이 8% 이상 빗나간 것만=헌장 5번 규칙 / 거래당 리스크 6%·Kelly=STEP 3 / 시장 바뀌면 전략 전환=48시간 점검.

1. **STEP 1 봇 만들기 (10분)**: 앱 설치 → Cursor 계정 로그인(브라우저) → 첫 안내 후 `Meet a future teammate` 화면에서 `Create your own` → 이름(아무거나), 맡을 일 하나(Settings의 Title 칸), 설명(Description 칸) 입력. 만든 뒤 오른쪽 위 톱니로 수정 가능. 봇 하나에 일 하나가 원칙(맥락이 쌓임).
   - 맡을 일: "폴리마켓 모의 거래". 설명 뼈대: 10분마다 시장을 훑고 X 반응을 읽어 가격이 틀린 시장을 찾고, 켈리 기준으로 금액을 정해 `trades.txt`에 **가상 거래로만** 기록하며 실제 주문·로그인·지갑 연결은 하지 않는다.
   - 메시지를 보낼 수 있으면 준비 완료. 클라우드 컴퓨터라서 노트북을 덮어도 봇 작업은 계속됨.
   - ❌ 처음부터 지갑 키/비밀번호를 채팅에 붙여 로그인 위임 → ✅ 첫 주는 로그인 없이 공개 데이터만. 비밀번호·인증 코드는 채팅에 붙여넣지 말고 화면을 넘겨받아 사람이 직접 입력(공식 문서 안내).
2. **STEP 2 시장 1,000개 받아서 거르기 (5분, 선택 실습)** — 코딩 없이 봇만 쓰려면 STEP 4로 직행 가능.
   ```
   mkdir grok-paper && cd grok-paper
   python3 --version
   curl --version
   ```
   - 예: Python 3.9.6, curl 8.7.1. python3 첫 실행 시 Command Line Tools 설치 창이 뜨면 설치 후 재실행.
   ```
   for o in 0 100 200 300 400 500 600 700 800 900; do curl -s "https://gamma-api.polymarket.com/markets?active=true&closed=false&limit=100&offset=$o" -o "page$o.json"; done
   python3 -c 'import json,glob; d=[m for f in glob.glob("page*.json") for m in json.load(open(f))]; json.dump(d,open("markets.json","w")); print(len(d), "markets")'
   ```
   - 기대 출력 `1000 markets`. 0이나 오류면 내 통신망에서 Gamma API가 막힌 것일 수 있음 → 같은 명령을 봇의 클라우드 터미널에서 실행.
   - 필터(유동성 $5,000 미만 제외, 2시간 내 종료 제외):
   ```
   python3 -c 'import json,datetime as d; now=d.datetime.now(d.timezone.utc); m=json.load(open("markets.json")); ok=[x for x in m if float(x.get("liquidityNum") or 0)>=5000 and x.get("endDate") and d.datetime.fromisoformat(x["endDate"].replace("Z","+00:00"))>now+d.timedelta(hours=2)]; print("후보", len(ok), "개"); [print(x["question"], x["outcomePrices"]) for x in ok[:3]]'
   ```
   - 예: `후보 837 개` + 질문 3개(끝의 두 숫자=예·아니오 지분 가격, 0.986=98.6%).
   - ❌ 주소 하나에 `limit=1000`으로 한 번에 요청(2026-10-03 실측 시 100개만 옴) → ✅ 100개씩 나눠 받기.
3. **STEP 3 하프 켈리 금액 (5분)**: 가격 P, 내 추정 확률 p.
   ```
   b = (1 - P) / P
   f = (b * p - (1 - p)) / b
   ```
   - f의 절반(하프 켈리)만 쓰고, 그래도 잔고의 6%를 넘으면 6%로 자름. f ≤ 0이면 거래 안 함.
   ```
   python3 -c 'P,p,bank=0.62,0.74,50; b=(1-P)/P; f=(b*p-(1-p))/b; print(round(f*100,1), round(f/2*100,1), round(min(f/2,0.06)*bank,2))'
   ```
   - 기대 출력 `31.6 15.8 3.0` (풀 켈리 % / 하프 켈리 % / 6% 상한이 이겨 실제 베팅 $3.0).
   - ❌ "확신이 크니까 잔고 절반"처럼 감으로 금액 결정 → ✅ 하프 켈리 계산 + 6% 상한(작은 우위에 작게 여러 번).
4. **STEP 4 헌장 프롬프트(모의 모드) 로드 (10분)**: Grok Bot 대화창의 첫 메시지로 붙여넣음. 원래 헌장의 규칙·숫자는 두고 실주문만 가상 기록으로 교체한 버전.
   - **프롬프트 뼈대**: 역할=폴리마켓 자율 트레이더이되 **모의 거래 모드**(주문·로그인·지갑 연결·입출금 절대 금지, 모든 거래는 `trades.txt`에 가상 기록). 슬롯: 가상 시작 자본 $50, 목표 월 $60 구독료 수익(원래 봇의 생존 조건 숫자를 그대로 둠), 잔고 0이면 꺼짐. 10분 루프:
     1. Gamma API에서 진행 중 시장 최대 1,000개(100개씩), 2시간 내 종료 또는 유동성 $5,000 미만 제외
     2. 시장별 정산 규칙을 끝까지 읽고 결과를 정하는 공식 출처 찾기
     3. X에서 실시간 반응 수집(계정 신뢰도·최신순 가중, 유료 홍보·봇 무시)
     4. 정산 규칙+X 반응+공개 데이터로 적정 확률 산정
     5. 적정 확률과 가격이 8%p 넘게 다른 시장만 표시
     6. CLOB 호가창에서 슬리피지 3% 이내로 전량 청산 가능할 때만 진행
     7. 켈리 금액의 절반만, 거래당 잔고 6% 이내, 동시 보유 5개 이하
     8. `trades.txt`에 시장·적정 확률·진입 가격·금액·청산 조건·이유 기록(청산 조건은 진입 전에)
     9. 보유 포지션 점검: 가격 차이 소멸 / 적정 확률 5포인트 넘게 변동 / 1시간 내 정산이면 청산 기록. 가상 자금 추가 금지.
     - 추가 제약: 공식 정산 출처를 못 찾은 시장은 거래 금지. 잔고가 고점 대비 40% 줄면 거래 중단 + `trades.txt`에 사후 분석 + 다른 일보다 먼저 나에게 메시지.
     - 마무리 요청: 이 루프를 10분마다 실행하는 루틴으로 만들고 다음 실행 시각 보고.
   - 성공 신호: 대화 중 회색 글씨로 `Created routine`+루틴 이름, 봇이 다음 실행 시각 알림. 대화창 오른쪽 패널 `View conversation details` > `Routines`에서 일정 확인.
   - ❌ "폴리마켓에서 돈 벌어 와"처럼 목표만 → 멈춤 조건 없는 에이전트는 무모해짐. ✅ 거래당 6%, 동시 5개, 고점 대비 40% 손실 시 중단 같은 숫자 한계 먼저.

**48시간 점검과 전략 전환**: 첫 이틀은 몇 시간마다 `trades.txt` 확인.
- 표시된 시장 3개의 질문·정산 규칙·현재 가격 원문을 봇에게 보이게 해, 봇의 적정 확률에 내가 동의하는지 직접 판단(한국에선 폴리마켓 사이트가 막혀 있으니 Gamma API 원문 기준).
- 모든 거래가 잔고의 6% 이하인지(15% 같은 값이 보이면 켈리 단계 고장), 진입 전 청산 조건이 있는지("62에 샀음"만 있으면 도박) 확인.
- 원래 봇은 잔고가 $11까지 떨어졌다가 스스로 정산 규칙이 명확한 날씨 시장(관측소 기록 하나로 정산)으로 옮겨 회복했다고 공개됨. 이 자료는 전략 전환을 사람이 승인하게 바꿈(공식 문서도 먼저 제안·시스템 변경은 승인 권장). 40% 손실로 멈추면 봇에게 질문: 정산 규칙이 가장 분명하고 예측하기 쉬운 시장 분야는 어디인지, 옮길 분야·이유·바꿀 규칙을 **제안만** 하고 내가 승인하기 전에는 바꾸지 말 것. 승인 전 `trades.txt` 규칙이 그대로인지도 확인.

## 핵심 팁 · 주의사항
- 한국: 2026-08-18 방송미디어통신심의위원회 의결로 Polymarket 접속 차단, 공식 문서도 한국을 웹사이트 신규 주문 불가 지역으로 표기 → 그래서 입금·로그인·주문·구독료 자동 출금은 빼고 모의까지만. 실거래 전환은 법/지역 규정 확인 전까지 금지.
- 봇 컴퓨터는 Cursor 클라우드. 주문 가능 여부는 그 컴퓨터 접속 위치로 판정되나 위치는 문서에 없음.
- 루틴 최소 실행 간격은 문서화 안 됨 → 루틴 생성 후 `View conversation details > Routines`에서 실제 일정·최근 실행 기록 확인. 오래 접속하지 않으면 봇이 루틴 유지 여부를 묻고 응답이 없으면 일시정지할 수 있음.
- 10분 루프는 사용량을 빨리 소모(유료 플랜은 주 단위 초기화, 체험 크레딧은 에이전트 단계·토큰만큼 줄어 한 번에 거의 소진 가능).
- "$50 → $5,273 / 48시간"은 작성자 공개 주장일 뿐 보장 아님. 이 자료의 숫자는 규칙의 기준값.
- 봇의 X 여론 기반 확률 추정은 스스로 검증하지 못함 → 48시간 점검에서 사람이 대조 필수. 실거래는 수수료·슬리피지로 모의 결과와 다를 수 있음.
- 지갑 키·시드·비밀번호·인증 코드는 채팅에 붙여넣지 말 것.
- "구독료 못 벌면 죽는다" 류 목표는 무리한 거래 압력이 될 수 있음 → 6%/40% 하드 리밋이 안전장치.

## 문제 해결
- 거래가 하나도 없음: 8%p 기준은 일부러 엄격. 없는 날도 정상이며 5%p 아래로 내리면 잡음 증가.
- 후보를 찾았는데 기록이 없음: 대부분 호가창 확인(전량 청산 불가)에서 걸려 건너뜀 → 정상 동작.
- 큰 손실 없이 잔고가 서서히 감소: 슬리피지·수수료 → 유동성 기준 $10,000, 슬리피지 한도 2%로 상향.
- Gamma API 결과가 0/오류: 통신망 차단 가능 → 봇의 클라우드 터미널에서 실행.
