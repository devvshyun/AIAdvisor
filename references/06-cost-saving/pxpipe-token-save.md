# 같은 Fable, 청구서만 반으로 줄이는 법 (pxpipe-proxy)
- 도구·주제: pxpipe-proxy + Claude Code · 비용 절약 / 컨텍스트 이미지 압축 (5분 읽기, STEP 3개, 2026-08-06 갱신)
- 한 줄 요약: 시스템 프롬프트·도구 설명·지난 대화 같은 덩치 큰 맥락을 촘촘한 이미지로 바꿔 보내는 로컬 프록시를 켜고 Claude Code를 연결해 입력 토큰(청구서)을 줄인다. 모델·출력은 그대로.

## 언제 쓰나
- 코드·JSON·로그가 많은 Claude Code 작업에서 월말 입력 토큰 청구서가 부담될 때
- 원리: 큰 맥락이 매 요청마다 텍스트로 다시 실려 입력 토큰을 태움. 이미지의 토큰값은 글자 수가 아니라 픽셀 크기로 고정되므로 빽빽한 코드·JSON·로그일수록 같은 내용이 훨씬 적은 토큰. 압축은 나가는 요청만이며 모델 답변(출력)은 건드리지 않음. 최근 대화는 텍스트로 두고 오래된 덩치만 이미지로 바꿈.

## 준비물 / 필요 도구
- pxpipe (npm 패키지명은 `pxpipe-proxy`, 실행 명령은 pxpipe. `npx pxpipe`는 "찾을 수 없음" 오류). 원문에 GitHub URL은 없음. 무료 오픈소스, 내 컴퓨터에서 도는 작은 중계기(프록시).
- Claude Code가 정상 작동 중일 것
- Node.js 18+ (`node -v`가 v18 이상, 없으면 https://nodejs.org)

## 단계별 방법
### 30초 컷 (명령만)
① 새 터미널에서 프록시 켜기(이 창은 닫지 말 것)
```bash
npx pxpipe-proxy@latest
```
② 다른 터미널에서 Claude를 프록시로 연결
```bash
ANTHROPIC_BASE_URL=http://127.0.0.1:47821 claude
```
③ 브라우저로 절감 확인: `http://127.0.0.1:47821/`

### STEP 1. 중계기 켜기 (30초)
- 설치할 것 없이 새 터미널 창에서 `npx pxpipe-proxy@latest`.
- 확인: 잠시 뒤 `proxy on 127.0.0.1:47821` 비슷한 문구가 뜨면 켜진 것.
- 이 창이 중계기이므로 닫으면 꺼짐. 작업은 새 창에서.

### STEP 2. Claude를 중계기로 연결 (10초)
- 다른 새 터미널에서 평소 `claude` 대신:
```bash
ANTHROPIC_BASE_URL=http://127.0.0.1:47821 claude
```
- 확인: 평소처럼 클로드가 뜨고 대화되면 연결된 것(뒤에서 큰 맥락이 이미지로 바뀌어 나감).
- 매번 치기 귀찮으면 `~/.zshrc` 또는 `~/.bashrc` 맨 아래에 추가 → 이후 `claude`만 쳐도 항상 프록시 경유. 되돌리려면 그 줄 삭제:
```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:47821
```

### STEP 3. 얼마나 아꼈는지 보기
- 브라우저에서 `http://127.0.0.1:47821/` — 텍스트가 이미지로 바뀐 실제 화면을 나란히 보여 주고 지금까지 아낀 토큰·비용을 실시간 집계. 화면 안 kill switch로 압축을 잠깐 멈추고 원래대로 돌려볼 수도 있음.

### (선택) Fable 외 모델도 압축
- 기본은 Fable 계열만 압축. 제작자 실측: Fable에서는 새 산수 문제 100/100, 상태 추적 18/18을 텍스트와 동일하게 맞힘.
- Opus·GPT·Grok도 켤 수 있으나 기본은 꺼짐: 빽빽한 이미지에서 12자리 같은 정확한 문자열을 놓칠 확률이 Fable보다 높기 때문. 원하는 사람만 직접 켜도록 한 것이 제작자 입장.
```bash
PXPIPE_MODELS=claude-fable-5,grok-4.5 npx pxpipe-proxy@latest
```
- 켠 뒤엔 중요하지 않은 짧은 작업으로 먼저 답 품질을 테스트.

### 끄기
- 중계기 창에서 `Ctrl + C`. `~/.zshrc` 등에 export를 넣었다면 그 줄을 지우면 클로드가 원래대로 직접 연결.

## 문제 해결 (FAQ)
- `npx pxpipe`가 "찾을 수 없음": 패키지명은 `pxpipe-proxy` → `npx pxpipe-proxy@latest`.
- "포트가 이미 사용 중"(47821): 포트를 바꿔 켜기 `PORT=47822 npx pxpipe-proxy@latest` 그리고 연결 주소도 `http://127.0.0.1:47822`로 변경.
- 대시보드 절약이 1%뿐: 이미 캐시가 많이 걸렸거나 코드보다 줄글 위주라서. 압축은 코드·JSON·로그처럼 빽빽한 입력에서 이득이 큼. 이득 없는 요청은 텍스트로 그대로 통과시키므로 손해 구조는 아님.
- 답 품질 저하 여부: 기본 Fable에서는 산수 100/100, 상태 추적 18/18로 동일했다는 제작자 실측. 바이트 단위가 걸린 경우(12자리 문자열 정확 복원 등)는 손실 가능.
- 실제 절약폭: 제작자 공개 테스트 스냅샷에서 전체 청구액 기준 대략 절반 안팎(작업 종류별 편차 큼). 정확한 수치는 내 대시보드에서 확인.

## 핵심 팁 · 주의사항
- ⚠️ 손실이 있을 수 있는 압축: 요지 파악엔 강하나 원문 완벽 복원은 보장 안 됨.
- ⚠️ 비밀번호·API 키·해시·정확한 ID처럼 글자 하나도 틀리면 안 되는 값은 드물게 잘못 읽힐 수 있음 → 바이트 단위로 정확해야 하는 값은 텍스트로 유지되게 두기.
- 출력은 안전: 압축은 보내는 요청뿐이고 모델 답변은 손대지 않음.
- 품질 수치(산수 100/100 등)와 "청구서 약 절반"은 모두 제작자 자체 측정치 → 내 작업 기준으로 대시보드 확인.
- (일반 주의) 내 API 트래픽이 로컬 프록시를 거치고 npx로 외부 패키지를 실행하므로 민감 프로젝트 전에는 패키지 소스를 검토하는 편이 안전.
- 도구 자체는 무료.
