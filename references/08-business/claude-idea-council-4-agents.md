# 내 아이디어를 6개월 만들기 전에 뜯어보는 네 자리 (아이디어 검토 에이전트 4개)
- 원문: https://lazyowen.com/guides/claude-idea-council-4-agents
- 도구·주제: Claude Code(서브에이전트/스킬) 또는 claude.ai 프로젝트 · 아이디어 검증 (2026-09-14 공개, 검증 환경 Claude Code v2.1.270, STEP 4개 · 약 22분)
- 한 줄 요약: 지지자·회의론자·투자자·판사 네 역할을 한 번만 만들어 두고 순서대로 돌려 "만든다 / 고치고 만든다 / 접는다" 중 하나의 판결을 받는다.

## 언제 쓰나
- AI에게 아이디어를 물으면 칭찬만 돌아와서(한 대화가 찬성·반대를 동시에 맡아 얼버무림) 믿기 어려울 때
- 사업/서비스 아이디어를 6개월 만들기 전에 약점부터 검증하고 싶을 때
- 새 프로그램이 아니라 역할 지시문 4개를 만드는 것. 설치할 앱도 새 구독료도 없음

## 준비물 / 필요 도구 (이름 + 공식 링크)
- Claude Code: https://github.com/anthropics/claude-code (Anthropic, 스타 144,971 / 2026-09-14, 오픈소스 아님·Anthropic 상업 약관). Pro·Max·Team·Enterprise 또는 콘솔 계정 필요(무료 요금제 불가) · 설치 https://code.claude.com/docs/en/setup · 서브에이전트 https://code.claude.com/docs/en/sub-agents · 스킬/슬래시 https://code.claude.com/docs/en/slash-commands
- 또는 claude.ai 프로젝트: https://claude.ai/projects (무료 계정도 프로젝트 5개까지) · 소개 https://support.claude.com/en/articles/9517075-what-are-projects · 생성/관리 https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects
- OS: macOS 13.0+, Windows 10 1809+, Ubuntu 20.04+ (터미널 방식). 프롬프트 4개는 그냥 글자라 자유롭게 수정 가능
- 용어: 역할 자리=지시문을 미리 저장해 둔 공간(Claude Code는 `~/.claude/agents`의 파일 하나, claude.ai는 프로젝트 하나), 넘기기=앞 역할의 답을 다음 역할 입력에 통째로 붙여 주는 일

## 단계별 방법
**Quick Start** — 역할 파일을 넣을 폴더 만들기(비어 있으면 아무것도 안 나옴)
```bash
mkdir -p ~/.claude/agents
ls ~/.claude/agents
```
Claude Code가 없으면(설치 후 `2.1.270 (Claude Code)` 같은 버전이 나오면 준비 완료):
```bash
curl -fsSL https://claude.ai/install.sh | bash
claude --version
```

**설치·검증 위임 프롬프트 뼈대 (Claude Code)**
- 역할: 아이디어 심사용 네 역할(지지자·회의론자·투자자·판사)을 설치하고 검증하는 담당. 맥락: 역할 파일도 판결 노트도 없는 상태
- 채울 곳: [OS·셸], [내가 쓰는 AI 도구: Claude Code 또는 claude.ai 프로젝트], [목표 한 줄 — 예: 만들기 전에 약점을 듣고 싶다]
- 작업 4단계: ① `claude --version`, `ls ~/.claude/agents`(이미 4개 있으면 재생성 금지, 파일명만 보고) ② `mkdir -p ~/.claude/agents` 후 네 프롬프트를 `believer.md`·`skeptic.md`·`investor.md`·`judge.md`로 저장(각 파일 맨 위에 `name`, `description` YAML 앞머리) ③ `ls ~/.claude/agents | wc -l`로 4개 확인, 새로 켠 Claude Code에서 "believer 에이전트로 이 아이디어를 봐 줘"로 실제 응답 확인 ④ 네 자리의 역할과 호출 순서를 5줄 이내로 설명
- 제약: `~/.claude/agents` 밖과 현재 작업 프로젝트 폴더에는 쓰지 말 것, 네 자리 외 역할 추가 금지, sudo 금지. 검증: 4개 파일 존재 + believer가 찬성 근거만 말함. 하나라도 실패하면 완료 보고 금지

**STEP 1. 판결 쌓을 자리 만들기 (2분)** — 판결=판사가 마지막에 내는 한 줄 결론(만든다/고치고 만든다/접는다)
```bash
mkdir -p ~/idea-council
printf '# 아이디어 판결 기록\n\n' > ~/idea-council/verdicts.md
cat ~/idea-council/verdicts.md      # "# 아이디어 판결 기록" 이 보이면 성공
```
- 터미널을 안 쓰면 메모 앱/노션 페이지도 가능. 네 자리가 전부 같은 곳을 보고, 노트가 비면 내일 처음부터 다시 설명하게 됨
- ❌ "내 아이디어 어때? 될 것 같아?" → ✅ "아이디어를 줄게. 지지자 역할로만 답해. 찬성 근거만 말하고 우려는 적지 마." (시선을 하나로 묶어 도망갈 곳을 없앰)

**STEP 2. 역할 네 자리 설치 (5분)** — 각각 `~/.claude/agents/<이름>.md`로 저장. Claude Code는 파일 맨 위 `---` 사이에 `name`, `description` 앞머리 포함. claude.ai는 프로젝트 4개를 만들어 "프로젝트 지침 설정"에 본문만(앞머리 3줄 제외) 붙여넣기
| 역할(파일) | description 취지 | 하는 일 | 마지막 출력 |
|---|---|---|---|
| 지지자 `believer.md` | 아이디어의 가장 강력한 찬성 근거를 만듦, 첫 번째 자리 | 누가 절실히 필요로 하고 지금은 대신 무엇을 하나 / 왜 하필 지금인가 / 잘 풀렸을 때 최고 모습 / 이기게 만들 불공정한 강점. 얼버무리거나 "상황에 따라 다르다" 금지, 응원단장 금지, 항목별 짧은 한 문단 | 아이디어 전체가 걸고 있는 단 하나의 베팅 |
| 회의론자 `skeptic.md` | 약점 공격·치명적 결함 탐색, 두 번째 자리 | 죽어 마땅하면 죽이는 역할. 아이디어와 지지자 주장을 읽고, 누가 왜 돈을 내지 않나 / 이미 해결 중인 경쟁자·공짜 우회로 / 만든 사람이 가까워서 못 보는 맹점 / 가장 빨리 죽는 단 하나의 경로. 칭찬 금지 | 치명적 결함: 그것이 사실이면 만들면 안 된다는 단 하나의 조건 |
| 투자자 `investor.md` | 실제 결제 여부와 속도만 판단, 세 번째 자리 | 아이디어와 앞 두 주장을 읽고, 좋아요가 아니라 실제로 돈을 낼 증거가 있나 / 첫 실제 매출 시점 / 이번 주 안에 수요를 증명할 가장 싼 테스트 하나 / 본인 돈을 넣겠나. 무뚝뚝하게 숫자로, 비전 이야기 금지 | 투자 예/아니오 + 그 판단을 바꿀 숫자 하나 |
| 판사 `judge.md` | 앞 세 주장을 읽고 만든다·고친다·접는다 중 하나로 판결, 반드시 마지막 | 아이디어와 세 역할의 말을 모두 읽고 정직하게 저울질, 양다리 금지. 판결 + 가장 큰 리스크 한 줄 + 코드 한 줄 쓰기 전 해 볼 10분짜리 테스트 하나 + (고치고 만든다면) 무엇을 정확히 바꾸면 만든다로 넘어가는지. 그 뒤 아이디어·판결·리스크를 공유 노트에 저장 | 판결 한 줄 |
(각 역할 지시문의 정확한 문장은 원문에서 복사. 위 표가 역할/입력/출력 골격)
```bash
ls ~/.claude/agents      # 파일 4개가 보이면 완료
```
- 새로 만든 폴더는 이미 켜진 세션이 못 알아챔 → Claude Code를 껐다 다시 켜기

**STEP 3. 순서대로 돌리고 판결 받기 (10분)** — 이 자료의 핵심. 순서를 어기면 의미가 사라짐
1. 지지자: `believer 에이전트로 답해 줘. 아이디어: <한 줄 아이디어>` → 누가 절실한지·왜 지금·최고 모습·불공정한 강점이 문단별로 나오고 마지막에 베팅 한 줄이면 정상
2. 회의론자: `skeptic 에이전트로 답해 줘. 아이디어: ... 지지자의 주장: <지지자 답 전체>` → 칭찬 없이 공격만, 마지막에 치명적 결함 한 줄이면 정상
3. 투자자: 같은 방식으로 앞의 두 답을 모두 붙여 전달
4. 판사: `judge 에이전트로 답해 줘. 아이디어: ... 지지자: <전체> 회의론자: <전체> 투자자: <전체> 판결을 내리고, 아이디어와 판결과 리스크를 ~/idea-council/verdicts.md 에 추가해 줘.` → 판결 한 줄, 리스크 한 줄, 10분 테스트 하나가 나오고 노트가 갱신되면 한 바퀴 완료
- ❌ 네 자리에 각각 아이디어만 따로 던지고 내가 모아 읽기(서로의 말을 못 읽는 독립 감상문 네 개) / 판사를 먼저 부르기(나머지 셋이 판결 변호로 변해 다시 예스맨) → ✅ 앞사람 답을 그대로 붙여 다음 자리로 넘기고 판사는 맨 마지막에 딱 한 번

**STEP 4. (선택) 명령 한 줄로 묶기 (5분)** — 손으로 한 바퀴 돌려 본 뒤에. 슬래시 명령=대화창에 `/이름`으로 저장된 지시문을 불러오는 기능
- 원문 명령은 줄바꿈이 사라져 `~/.claude/skillsroastcat`처럼 붙어 보이지만 실제로는 `mkdir -p ~/.claude/skills/roast` 다음 줄에 `cat > ...` 형태의 heredoc임(오타 아님). 복원하면:
```bash
mkdir -p ~/.claude/skills/roast
cat > ~/.claude/skills/roast/SKILL.md <<'EOF'
---
description: 아이디어 하나를 지지자·회의론자·투자자·판사 순으로 심사하고 판결을 노트에 저장한다.
---
아래 아이디어를 네 역할에 순서대로 넘겨라. 순서를 바꾸지 마라.
1. believer 에이전트를 부르고 답을 보관한다.
2. skeptic 에이전트를 부르되 1의 답을 함께 준다.
3. investor 에이전트를 부르되 1과 2의 답을 함께 준다.
4. judge 에이전트를 부르되 1, 2, 3의 답을 모두 준다.
5. 판사의 판결과 리스크를 ~/idea-council/verdicts.md 에 날짜와 함께 추가한다.
마지막에 판결 한 줄, 리스크 한 줄, 10분 테스트 하나만 요약해서 보여 준다.
EOF
ls ~/.claude/skills/roast
```
- Claude Code 재시작 후 `/roast <아이디어>`
- 되돌리기(지우면 설정이 따로 남지 않음):
```bash
rm -rf ~/.claude/skills/roast ~/.claude/agents/believer.md ~/.claude/agents/skeptic.md ~/.claude/agents/investor.md ~/.claude/agents/judge.md
```

## 핵심 팁 · 주의사항
- 결제 증거를 만들어 주지 않음: 투자자는 "이번 주에 이 테스트를 하라"고 좁혀 줄 뿐, 실제 고객 확인은 내 몫
- 아이디어 한 줄이 모호하면 판결도 일반론 → 누가 쓰는지·무엇 대신 쓰는지·돈은 누가 내는지 세 가지를 아이디어 줄에 넣기
- 앞 답변 누락, 판사 조기 호출 → 효과 없음(가장 흔한 실패)
- 계속 "접는다"가 나오면 회의론자 답이 과한 것 → 투자자에게 "마음을 바꿀 숫자 하나"를 다시 묻고, 현실적인 값이면 판결이 "고치고 만든다"로 바뀜
- claude.ai 프로젝트 방식은 파일 쓰기 불가 → 판결을 복사해 프로젝트 지식에 직접 업로드
- 판결은 참고, 결정은 본인. 접는다가 나와도 계속할 수 있지만 그땐 회의론자의 치명적 결함을 알고 시작
- 네 개가 한 세트(지지자 없으면 최고 모습을 못 보고, 회의론자 없으면 예전과 같고, 투자자 없으면 좋아요와 결제를 구분 못 하고, 판사 없으면 결론이 안 남). 다른 AI 도구에서도 역할 지시문을 저장할 수 있으면 사용 가능

## 문제 해결
- 에이전트가 없다고 나옴: `~/.claude/agents`가 세션 시작 전에 없었음 → Claude Code 재시작
- 판결이 매번 접는다: 위 팁 참고
- 노트에 판결이 안 쌓임: 판사 프롬프트 마지막에 저장 지시가 있는지 확인. claude.ai 프로젝트는 직접 업로드
