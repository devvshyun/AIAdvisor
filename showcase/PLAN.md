# 도구별 비포·애프터 계획

카탈로그 46개 중 이 PC에서 계정 없이 돌릴 수 있는 도구를 골라, 직접 돌려 봐야 아는 것과 중요도가 높은 것부터 결과물을 만든다. 분류 기준일: 2026-11-06.

## 요청하면 이렇게 진행한다

이 문서는 실행 계획이 아니라 대기 목록이다. 사용자가 요청할 때만 진행한다.

| 사용자 요청 예 | 진행 범위 |
|---|---|
| "쇼케이스 중요도 높음 진행해" | 1번 표 11개를 표 순서대로 |
| "쇼케이스 중간도 진행해" | 3번 표 10개 |
| "graphify 쇼케이스 돌려줘" | 그 도구 하나 |
| "이미 써 본 것 결과 정리해" | 2번의 8개를 결과물 형식으로 옮기기 |

진행할 때 지킬 것:
- 시작 전에 이 문서의 분류가 지금도 맞는지 카탈로그(`maintained`, `cost`, `hands_on`)와 대조한다. 바뀌었으면 표를 먼저 고친다.
- 설치가 필요한 도구는 설치 명령과 위험을 보여 주고 승인을 받는다(카탈로그 `install`, `risks`). 끝나면 지우거나 끄고, 남겨 둔 것은 이유를 적는다.
- 같은 분야는 같은 비포 재료와 같은 요청 문장으로 비포와 애프터를 만든다.
- 도구 하나가 끝날 때마다 결과를 보여 주고 다음으로 넘어간다.

준비해 둔 것(진행할 때 쓴다. 아직 한 번도 돌려 보지 않았으니 처음 쓸 때 동작부터 확인한다):
- `fixtures/web/index.html`: 웹 디자인 비포 재료(AI 티 나는 랜딩 페이지)
- `fixtures/coding/`: 문제를 심어 둔 코딩 비포 재료(참조 찾기, 흐트러진 포맷, 위험한 코드)
- `fixtures/prompts.md`: 비포와 애프터에 똑같이 넣을 요청 문장
- `scripts/measure.py`: `claude -p`로 같은 요청을 여러 번 돌려 토큰·턴·시간·비용을 `<id>/runs/`에 남긴다
- `scripts/shot.py`: 정해진 화면 폭으로 캡처
- `scripts/new.py`, `TEMPLATE.md`: 도구별 결과 문서 `<id>/README.md` 만들기

## 분류 기준

- **로컬 가능**: 유료 플랜이나 새 계정 없이 이 PC(또는 이 저장소의 GitHub Actions)에서 돌릴 수 있다.
- **확인 방식**
  - **돌려 봐야 앎**: 결과가 모델의 판단이나 실제 환경에 달려 있어서, 문서만으로는 효과를 말할 수 없다(디자인 결과, 리뷰 품질, 토큰 절감량 등).
  - **말로 충분**: 동작이 문서에 분명하고 결과가 예측 가능하다. 또는 다른 도구와 역할이 같아서 그쪽 결과로 설명할 수 있다.
- **중요도**
  - **높음**: 레시피의 핵심 단계이거나, 평가 답변에서 자주 추천되거나, 효과를 숫자로 보여 줄 수 있다.
  - **중간**: 쓸모는 있지만 같은 역할의 대표 도구가 따로 있거나, 특정 상황에서만 필요하다.
  - **낮음**: 겹치는 도구가 있고 설명으로 충분하거나, 쓰는 상황이 좁다.

## 결과물 형식

도구마다 `showcase/<id>/README.md` 한 장에 아래를 적는다.

- 비포: 재료와 그 상태(캡처, 점수, 토큰 수)
- 실행: 설치 명령, 실제로 돌린 명령이나 프롬프트, 걸린 시간
- 애프터: 결과(캡처, 점수, 목록)
- 판단: 좋았던 점, 아쉬운 점, 다시 쓸지 한 줄

끝나면 카탈로그 `hands_on`과 레시피 "써 보니"에 한 줄씩 옮기고, 데모 페이지 카탈로그에서 그 결과로 연결한다.
